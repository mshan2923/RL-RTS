# RL 기반 RTS 유닛 AI

Unity DOTS(ECS) + Python(Stable-Baselines3 PPO)로 학습한 강화학습 에이전트를,
Unity InferenceEngine(Sentis)으로 실시간 추론 배포한 RTS 유닛 AI 프로젝트입니다.

## 개요

- 유닛은 **전진 / 후퇴 / 정지** 3개의 최소 액션만으로 구성되어 있습니다.
- 공격 같은 이질적인 행동은 별도 시스템으로 분리하고, 위치 평가(potential function) 설계만으로
  접근·거리 유지·공격성 기반 위치 선택까지 창발적으로 학습되도록 유도했습니다.

## 기술 스택

- Unity DOTS / ECS
- Unity InferenceEngine (Sentis)
- Python
- Stable-Baselines3 (PPO)
- TCP Socket 통신 (Unity ↔ Python)
- ONNX

## 파이프라인

```
Unity DOTS (Observation 생성)
        ↓  TCP (obs/action 직렬화)
Python SB3 PPO 학습
        ↓  ONNX Export
Unity Sentis 추론
```

## 핵심 기술적 도전 및 해결

### ECS 다중 시스템 간 관측값 동기화

DOTS 환경에서 여러 시스템이 병렬로 상태를 갱신하다 보니, "직전 프레임 값"을 갱신하는
책임이 두 시스템에 분산되어 실행 순서에 따라 관측값이 미묘하게 오염되는 문제가 있었습니다.
갱신 책임을 단일 지점으로 통일하여 해결했습니다. ECS의 병렬성과 강화학습의 프레임 단위
일관성 요구가 충돌하는 지점을 다루는 과정이었습니다.

### 보상 설계의 국소 최적점 문제

특정 행동(정지 등)이 안전하게 보상을 챙길 수 있는 조건에서, 정책이 그 행동 하나에
조기 수렴하는 현상이 반복되었습니다. 원인이 보상 항 하나(생존 보너스)에 있음을 특정하고
제거하여 해결했습니다. 여러 보상 항이 얽힌 상태에서 원인 하나를 특정하는 디버깅 과정이
까다로웠습니다.

### 보상 신호 통합 (Potential-based Reward Shaping)

거리, 맵 가장자리 등 서로 다른 절대값 보상 항을 단순 합산하면 상황마다 우연히 상쇄되는
지점이 계속 발생해 "하나를 고치면 다른 게 깨지는" 패턴이 반복되었습니다. 하나의
potential function으로 통합한 뒤 그 변화량(delta)만 보상으로 사용하는 방식으로
전환하여 해결했습니다.

### 행동 다양성 확보 (이산 파라미터)

공격성 파라미터를 연속값으로 두었을 때는 학습이 불안정했습니다. 이산값으로 전환하여
명확하게 구분되는 행동(후퇴 / 중립 / 근접)을 안정적으로 학습시킬 수 있었습니다.

## 최적화

- 공간 분할(Hex grid 기반 NativeParallelMultiHashMap)로 최근접 타겟 탐색
- 링(반경) 단위 탐색 중 즉시 팀 필터링 + 거리 비교를 끝내 이중 순회 제거

## 향후 계획

- 분대 단위 렌더링으로 시각적 유닛 수 확장
- 상황별 미션(공격 / 후퇴 / 채집 등) 선택 상위 정책 설계
